## Part 6: Backend API Routes

- [ ] Create Pydantic schemas in backend matching frontend `BoardData`:

- [ ] Implement backend API endpoints:
  - `GET /api/board`: Fetch the Kanban board JSON for the authenticated user.

- [ ] Implement database connection lifecycle in FastAPI (`lifespan`).
- [ ] Write backend unit tests using `pytest` and `httpx`:
  - Test fetching board returns seed data.
  - Test updating board persists modifications.
  - Test payload validation rejects invalid JSON shapes.

### Tests & Success Criteria
- Test: `pytest` runs and all backend API route tests pass.
- Test: `PUT /api/board` followed by `GET /api/board` returns updated state.
- Success Criteria: Robust CRUD endpoints for Kanban JSON with automated test coverage.

## Part 9: AI Structured Outputs

- [ ] Define Structured Output JSON schema using Pydantic / JSON Schema:
  - `message`: String response to the user.
  - `board_update`: Optional `BoardData` object representing the updated board (or `null` if no board change).
- [ ] Implement chat endpoint `POST /api/ai/chat`:
  - Inputs: user prompt, conversation history, current board JSON.
  - System prompt: instructions explaining role, constraints (only title and details on cards), and how to return structured updates.
  - Call OpenRouter with structured outputs or JSON mode.
  - If `board_update` is present, validate and persist to SQLite for the user.
- [ ] Write backend unit tests:
  - Test chat response without board modifications (e.g. "How many cards are in Done?").
  - Test chat response with card creation (e.g. "Add a card to Backlog called 'Write docs'").
  - Test chat response with card movement (e.g. "Move 'QA micro-interactions' to Done").

### Tests & Success Criteria
- Test: Backend tests verify AI returns structured JSON matching schema.
- Test: Verifying board state updates in database when AI generates modifications.
- Success Criteria: AI can accurately query, create, move, and edit cards through structured output.
